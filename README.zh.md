# 投诉归因分析平台设计规范（Image-to-Code）

本文档基于参考图提炼页面视觉、布局、组件、图表与动效规范，用于后续高保真还原「投诉归因分析平台」数据看板页面。

## 1. 页面整体气质与传递感觉

### 1.1 关键词

- **专业可信**：面向业务管理、投诉分析与风险监测，整体应呈现稳定、清晰、可解释的数据产品气质。
- **轻量智能**：通过 AI 预警建议、趋势分析、重点关注标签，体现智能辅助决策，但不应有强烈科幻感。
- **高效聚焦**：大量数据在同一屏纵向展开，视觉层级要帮助用户快速定位异常、增长、下降和重点问题。
- **清爽克制**：整体以白色、浅灰、浅蓝为主，减少高饱和大面积色块，避免压迫感。

### 1.2 视觉风格

- 使用 **浅色企业级数据看板** 风格。
- 背景留白充足，内容通过圆角卡片承载。
- 重要数据使用大字号与红/绿趋势色强调。
- 图表配色明亮但透明度适中，避免多个高饱和颜色互相抢夺。
- 卡片、筛选器、表格均使用细线边框与柔和阴影，保持精致、轻盈。

- 红/绿趋势色：约 **5%**，仅用于异常、涨跌、提醒，不可大面积铺满。

## 3. 字体选择、层级和大小规范

### 3.1 字体族

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
```

- 中文优先使用 **PingFang SC / Microsoft YaHei**。
- 数字可使用系统默认等宽感较弱的无衬线，不建议额外引入夸张数字字体。
- 所有文字保持清晰、现代、企业级，不使用衬线体、手写体、装饰体。

### 3.2 字号层级

| 层级 | 字号 | 行高 | 字重 | 用途 |
| --- | --- | --- | --- | --- |
| 页面 Logo/系统名 | 16px | 24px | 600 | 顶部「投诉归因分析平台」 |
| 一级模块标题 | 16px | 24px | 600 | 卡片标题，如「AI预警建议」 |
| 二级卡片标题 | 14px | 22px | 600 | 小卡片标题、表格标题 |
| 正文 | 13px | 20px | 400 | 表格内容、筛选项、描述文本 |
| 辅助文字 | 12px | 18px | 400 | 图例、单位、说明、同比文案 |
| 关键数字 | 24px | 32px | 700 | 总投诉量、月投诉量 |
| 次级关键数字 | 20px | 28px | 700 | 日投诉量、环比增长率 |
| 趋势数字 / 标签 | 12px | 18px | 600 | `+12.5%`、`-8.4%`、风险标签 |

### 3.3 排版规则

- 标题与内容间距：12px-16px。
- 数字与单位分离，单位用 12px、灰色。
- 趋势数字必须与箭头同色，上升为红色，下降为绿色。
- 表格内容默认 13px，表头 13px/600。
- 不要在同一区域混用过多字号，单张卡片最多 3 个字号层级。

## 4. 首屏布局结构

### 4.1 页面尺寸与整体容器

- 目标画布：桌面端 Web，推荐最小宽度 **1440px**。
- 页面背景：`#F5F7FB`。
- 顶部导航高度：**72px**。
- 主内容宽度：建议 **1080px-1120px**，居中显示。
- 主内容顶部与导航间距：**8px-12px**。
- 主内容纵向卡片间距：**12px**。

### 4.2 顶部导航

- 左侧：蓝色圆形/渐变 Logo，尺寸 **20px × 20px**；系统名距 Logo 10px。
- 中间导航：
  - 导航项间距 **72px-96px**。
  - 当前页「洞察分析」为蓝色文字 `#2F7CF6`，下方 2px 蓝色指示线，宽度约 36px。
  - 非当前项为 `#4B5563`。
- 右侧：头像 24px、欢迎语 13px、退出图标 16px。

### 4.3 首屏筛选区

- 白色卡片容器，高度约 **68px**，圆角 8px。
- 横向排列筛选项：日期、渠道、部门、场景、问题细项、查询按钮。
- 筛选控件高度 **32px**，圆角 6px，边框 `#E8ECF3`。
- 标签文字与输入框之间间距 8px；控件之间间距 18px-24px。
- 查询按钮宽 **52px-64px**，高 **32px**。

### 4.4 首屏核心区域

- 使用左右两栏布局，间距 8px-12px。
- 左侧趋势柱状图卡片：约占 **64%** 宽度，高度 **380px**。
- 右侧整体概览卡片：约占 **36%** 宽度，高度与左侧齐平。
- 左侧卡片包含：日/周/月 Tab、下载按钮、图例、堆叠柱状图。
- 右侧卡片包含：标题、四宫格核心指标、底部浅蓝洞察结论。

### 4.5 后续纵向结构

1. AI 预警建议卡片：整行，高度约 120px。
2. 分项表现对比：上方三张小卡片，下方表格。
3. 投诉类型趋势对比：整行折线图，高度约 420px。
4. 投诉明细：筛选栏 + 表格 + 分页，高度约 420px。

## 5. 按钮样式与状态规范

### 5.1 主按钮

- 用途：查询、当前选中的 Tab。
- 尺寸：高 32px；普通按钮宽 52px-72px；Tab 可按内容等分。
- 背景：`#2F7CF6`。
- 文字：白色，13px/600。
- 圆角：6px。
- Hover：背景 `#1F6BEA`，阴影 `0 4px 10px rgba(47, 124, 246, 0.22)`。
- Pressed：背景 `#155BD4`，按钮轻微下沉 1px。
- Disabled：背景 `#C9D8F5`，文字 `#FFFFFF`，不显示阴影。

### 5.2 次级按钮

- 用途：下载、查看详情、非选中 Tab。
- 背景：`#FFFFFF`。
- 边框：`#E8ECF3`。
- 文字：`#4B5563`。
- Hover：边框 `#2F7CF6`，文字 `#2F7CF6`，背景 `#F4F8FF`。
- Pressed：背景 `#EAF2FF`。

### 5.3 标签按钮 / 状态标签

- 紧急：红字 `#FF3B3B`，浅红底 `#FFF0F0`，边框 `#FFD1D1`。
- 高优先级：橙字 `#FF7A1A`，浅橙底 `#FFF6E8`。
- 重要关注：蓝字 `#2F7CF6`，浅蓝底 `#EAF2FF`。
- 标签高度：22px-24px，水平内边距 8px-10px，圆角 4px。

### 5.4 表格操作按钮

- 「洞察详情」为浅蓝底小按钮。
- 高度 24px，圆角 4px，文字 12px/600。
- 默认背景 `#EAF2FF`，文字 `#2F7CF6`。
- Hover 背景 `#DCEBFF`。

## 6. 卡片尺寸、边距、阴影细节

### 6.1 通用卡片

- 背景：`#FFFFFF`。
- 圆角：10px-12px。
- 边框：`1px solid #EEF2F7`。
- 阴影：`0 4px 14px rgba(31, 41, 55, 0.06)`。
- 内边距：顶部卡片 16px-20px；大型图表卡片 20px；表格卡片 18px 20px。
- 卡片间距：12px。

### 6.2 图表卡片

- 标题区高度：40px-48px。
- 图例与图表之间间距：16px。
- 图表绘图区需预留坐标轴标签空间：左侧 38px，底部 28px。
- 图表网格线使用 `#EEF2F7`，线宽 1px。
- 坐标轴文字使用 12px `#9CA3AF`。

### 6.3 指标概览卡片

- 顶部可使用浅蓝渐变装饰背景：`linear-gradient(135deg, #F8FBFF 0%, #EEF6FF 100%)`。
- 四宫格指标每格宽度 50%，高度约 110px。
- 中间分割线：`#EEF2F7`，1px。
- 底部洞察块：浅蓝底 `#F4F8FF`，圆角 8px，内边距 14px。

### 6.4 AI 预警卡片

- 外层卡片标题区白底。
- 内容横幅背景：`linear-gradient(90deg, #FFF8EC 0%, #FFFDF7 65%, #FFF4DC 100%)`。
- 横幅高度约 72px，圆角 8px。
- 左侧图标区域 40px-48px，建议使用柔和警灯/提醒图标。
- 文案中关键字用红色或蓝色高亮，但单行高亮不超过 3 处。

### 6.5 表格卡片

- 表头高度：44px，背景 `#F5F7FA`。
- 表格行高：42px-46px。
- 单元格水平内边距：16px。
- 行分割线：`#EEF2F7`。
- Hover 行背景：`#F8FAFF`。
- 分页区域高度：48px，右对齐。

## 7. 图片、图标与图表使用规则

### 7.1 图片与装饰图

- 页面不使用大幅照片，主要使用轻量插画与数据装饰图。
- 右侧概览卡片顶部装饰：建议尺寸 **120px × 72px**，放置在右上角，透明度 85%-100%。
- AI 预警右侧装饰：建议尺寸 **160px × 72px**，透明度 30%-45%，不可影响文字可读性。
- 装饰图应使用蓝色、橙色浅渐变，不使用写实纹理。

### 7.2 图标

- 导航 Logo：20px。
- 用户头像：24px。
- 筛选下拉箭头：12px。
- 下载图标：14px。
- 表格操作图标若有：14px。
- 图标线宽 1.5px-2px，圆角端点，风格统一。

### 7.3 图表比例

- 首屏柱状图绘图区：宽高比约 **2.2:1**。
- 趋势折线图绘图区：宽高比约 **3.2:1**。
- 环形图：直径 92px-110px，环宽 12px-14px。
- 小卡片趋势装饰图：宽 110px-130px，高 90px-110px，放在右侧偏下。

### 7.4 图表规则

- 堆叠柱状图柱宽：10px-14px，同组间距 8px-12px。
- 折线图线宽：2px，节点直径 4px-5px。
- 图例圆点/方块：8px × 8px，文本 12px。
- 数值标签只显示关键节点，避免整图拥挤；参考图可在折线节点上显示小号数值。

## 8. 动效规范

### 8.1 页面进入

- 页面主内容淡入并轻微上移。
- 触发：页面加载完成。
- 时长：240ms-320ms。
- 缓动：`cubic-bezier(0.2, 0, 0, 1)`。
- 强度：透明度 0 → 1，位移 8px → 0。

### 8.2 卡片 Hover

- 触发：鼠标悬停在可交互卡片或表格行上。
- 时长：160ms-200ms。
- 效果：阴影增强至 `0 8px 22px rgba(31, 41, 55, 0.09)`，或背景变为 `#F8FAFF`。
- 强度：仅轻微浮起，不做明显缩放；如需位移，最大 `translateY(-1px)`。

### 8.3 按钮交互

- Hover：160ms，颜色与阴影过渡。
- Pressed：80ms，`translateY(1px)`。
- Loading：查询按钮可显示 14px loading spinner，旋转周期 800ms-1000ms。

### 8.4 Tab 切换

- 触发：切换日线/周线/月线或趋势维度。
- 时长：180ms-240ms。
- 效果：选中背景滑动或淡入；图表内容淡出 80ms 后淡入 160ms。
- 强度：不做大幅横向移动，避免影响数据阅读。

### 8.5 图表加载

- 柱状图：柱子自下而上增长，时长 500ms-700ms，分组延迟 15ms-25ms。
- 折线图：线条从左到右描边出现，时长 600ms-800ms；节点延迟出现 100ms。
- 环形图：从 -90° 开始绘制，时长 600ms。
- 动效只在首次加载或数据切换时触发，不在滚动时反复播放。

### 8.6 数字变化

- 关键指标数字切换使用 count-up。
- 时长：500ms-800ms。
- 小数百分比保留 1 位。
- 若用户开启减少动态效果，应直接显示最终数字。

## 9. 响应式规则

- 1440px 及以上：内容区固定 1080px-1120px 居中。
- 1200px-1439px：内容区左右留 24px，左右两栏仍保持。
- 1024px-1199px：首屏左右栏比例调整为 60% / 40%，筛选项允许换行。
- 小于 1024px：首屏左右栏改为上下堆叠，表格允许横向滚动。
- 不建议为手机端重新设计复杂图表交互；若必须适配，优先保留核心指标与表格摘要。

## 10. 可访问性与可读性

- 正文与背景对比度至少达到 WCAG AA。
- 红/绿趋势不可只依赖颜色，必须同时使用箭头或 `+/-` 符号。
- 图表图例颜色应配合文字标签，不让用户仅凭颜色识别。
- 所有可点击元素最小点击区域不低于 32px 高。
- Focus 状态使用 `0 0 0 3px rgba(47, 124, 246, 0.18)`。

## 11. 明确禁忌：不要做什么

- **不要** 使用深色大背景或高对比黑色仪表盘风格；参考图是轻量白底企业后台。
- **不要** 大面积使用红色，即使页面展示投诉增长，也只能在趋势、标签和重点文案中点状使用。
- **不要** 使用拟物化强阴影、玻璃拟态、霓虹光效或复杂 3D 效果。
- **不要** 让图表颜色超过 7 个主分类色；超过时应归为「其他」。
- **不要** 在卡片内堆叠过多边框、分割线和背景色，避免视觉噪音。
- **不要** 使用过大的圆角；后台系统建议 6px-12px，避免变成移动端卡通风。
- **不要** 让表格行高过小；投诉内容需要可读，行高应保持 42px 以上。
- **不要** 将所有数据都做强动效；数据分析页面应以稳定阅读为主。
- **不要** 使用模糊、写实或情绪化照片作为背景。
- **不要** 让筛选区控件尺寸不一致；日期、下拉、按钮必须在同一基线上。
- **不要** 隐藏趋势方向；所有百分比变化必须明确上升/下降。
- **不要** 让 AI 建议看起来像广告横幅；它应是克制的信息提示模块。
- **不要** 在首屏加入过多营销文案，页面重点必须是投诉数据与归因洞察。
